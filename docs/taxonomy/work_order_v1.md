## Part 1. 명세서의 '승격 파이프라인' 검토

### 승격 파이프라인이란
초기 기획에 있던 흐름. 사용자가 자유 태그(예: `조개`)를 입력 → 같은 태그가 많이 쌓이면 → 운영자가 공식 태그로 "승격" → `promoted_from` 컬럼에 원래 자유 태그를 기록하는 구조였음.

### 지금은 필요 없는 이유
- 배포 사이트에 자유 태그 입력칸이 처음부터 없었음. 승격할 원재료가 없음
- 운영자만 주제를 추가하는 현재 방식 유지
- 그 역할은 Part 2의 **주제 제안 기능**이 대신함 (게시물에 데이터를 남기지 않고 운영자에게 신호만 보냄)

### Claude Code에 전달할 프롬프트 (Part 0 보고 후, 0-1에서 서술이 발견된 경우만)

```
CLAUDE.md에서 0-1로 찾은 승격 파이프라인·자유 태그 관련 서술을 아래 내용으로 바꾸는
수정안을 먼저 보여줘. 내가 확인하기 전에는 파일을 수정하지 마.

대체할 내용:
- 사용자 자유 태그 기능은 두지 않는다. 주제 태그는 운영자만 추가·수정·숨김할 수 있다.
- 사용자는 기록하기 폼의 '찾는 주제가 없나요?'로 주제를 제안할 수 있다.
  제안은 topic_suggestions 테이블에 저장되고, 운영자 주제 태그 관리 화면에서
  제안 횟수 순으로 확인한다.
- 운영자가 새 주제를 추가해도 기존 게시물에 소급해서 태그를 달지 않는다.
  (모든 태그는 작성자가 입력 시점에 직접 고른 것만 저장한다는 원칙 유지)
- promoted_from 컬럼은 사용하지 않는다. (DB에 이미 있으면 삭제하지 말고 그대로 둠)
```

## Part 2. 주제 제안 기능

### 판단: 외부 링크보다 입력값 저장이 나음

| | 구글폼 링크 | 입력값 저장 |
|---|---|---|
| 기록 흐름 | 기록 도중 앱을 벗어남. 폼 입력값 유지가 안 되면 작성 중이던 기록이 날아갈 수 있음 (0-7 확인 필요) | 화면을 벗어나지 않음 |
| 집계 | 다른 피드백과 섞여서 수작업으로 세야 함 | 같은 주제끼리 자동으로 묶여서 횟수 순으로 보임 |
| 맥락 | 어떤 책 때문에 필요했는지 모름 | 그때 고른 책이 함께 저장됨 |
| 작업량 | 없음 | 테이블 1개와 화면 2곳 (Claude Code 기준 1~2시간) |

→ **입력값 저장으로 진행.** 구글폼 링크(피드백 개선/제보)는 주제 영역이 아니라 마이페이지 등 일반 피드백 자리에 두는 걸 권장.

## 1. DB (SQL을 먼저 보여주고, 내가 Supabase에서 직접 실행할게)

topic_suggestions 테이블
- id: uuid PK
- user_id: 제안한 사용자 (기존 사용자 테이블 참조 방식을 따를 것)
- book_id: 제안할 때 선택되어 있던 책 (nullable, 책 삭제 시 null)
- text: 사용자가 입력한 원문, 최대 30자
- normalized: 집계용 정규화 값 (공백·가운뎃점(·)·슬래시·하이픈 제거, 소문자)
- status: 'pending' | 'added' | 'declined', 기본값 'pending'
- created_at
- 같은 사용자가 같은 normalized를 두 번 넣지 못하게 unique (user_id, normalized)

RLS
- insert: 로그인한 본인 것만
- select / update: 운영자만 (기존 운영자 확인 방식 사용)
- 일반 사용자는 조회 불가

## 2. 기록하기 폼 (/recommend/create)

※ Part 3에서 만들 '전체 주제' 바텀시트의 맨 아래에 배치함.
   Part 3보다 먼저 만든다면 지금의 주제 태그 영역 맨 아래에 임시로 두고,
   Part 3 작업 때 시트 맨 아래로 옮길 것.
배치:
- 접힌 상태: 회색 작은 텍스트 버튼 "찾는 주제가 없나요?"
- 누르면 그 자리에서 펼쳐짐 (다른 페이지로 이동하지 않음)
  - 입력칸 1개, placeholder: "예: 이사, 캠핑, 한글날"
  - 최대 30자
  - 버튼: "운영자에게 알리기"
  - 안내 문구(작게): "모인 의견을 보고 주제를 추가해요"
- 보내면 입력칸을 비우고 토스트: "알려주셔서 고마워요. 주제를 추가할 때 참고할게요."
- 기록 저장과 별개로 즉시 전송 (기록을 저장하지 않아도 제안은 남음)
- 그 시점에 책이 선택되어 있으면 book_id를 함께 저장
- unique 충돌(같은 사람이 같은 제안 반복)은 에러 없이 성공처럼 처리
- 입력한 주제를 이 게시물의 태그로 저장하지 않음
- 터치 영역 최소 44px

## 3. 운영자 주제 태그 관리 화면

기존 화면에 '사용자 제안' 섹션(또는 탭) 추가:
- 기본 필터: status = pending
- normalized 기준으로 묶어서 표시, 많이 제안된 순서로 정렬
  - 대표 표기 (가장 먼저 들어온 원문)
  - 제안 횟수
  - 마지막 제안일
  - 함께 저장된 책 제목 (최대 3개)
- 묶음 단위 버튼: [추가함] [보류]
  → 같은 normalized의 모든 행 status를 함께 변경
- [추가함]을 눌러도 태그가 자동으로 만들어지지 않음.
  태그 추가는 기존 태그 추가 기능으로 운영자가 직접 함
- 상단 필터: 대기 / 추가함 / 보류
